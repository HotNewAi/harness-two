# 架构总览

harness-two 是一套双 Agent 开发协作模板。它将实现与审查分成两个模型会话，并通过显式交接和逐轮复查形成质量闭环。当前仓库提供角色提示词、流程约定、仓库知识导航和辅助脚本；不包含模型 API 客户端或自动调度器。

## 协作拓扑

```text
用户目标与验收标准
        │
        ▼
Agent 1：实现、修改、验证
        │ 完整 diff + 验证事实
        ▼
Agent 2：只读独立审查
        │ 发现项 / 通过 / 阻塞
        ▼
Agent 1：逐项核实与修复 ── 未决决策 ──► 用户
        │ 新 diff 与验证
        └──────────────► Agent 2 复查
```

## 仓库组成

- `AGENTS.md`：入口与知识路由。
- `docs/AGENT_WORKFLOW.md`：双 Agent 的职责边界、交接材料、审查循环和停止条件。
- `docs/agent-prompts/`：实现者与审查者的可复用角色提示词。
- `docs/`：正式的仓库知识、计划、产品约束与历史记录。
- `scripts/`：项目初始化、计划和历史记录的辅助脚本。

## 边界和运行方式

- Agent 1 是本地工作树唯一写入者；Agent 2 只审查当前明确提供的需求、规则和 diff。
- 默认在独立上下文中审查，并按最多 3 轮处理；重要分歧、验证阻塞和超轮数未决风险交给用户。
- 审查通过不代表测试自动通过，也不代表用户已授权合并、发布或其他外部副作用。
- 宿主平台负责选择模型、配置凭据、隔离会话和交接。若平台不支持自动调度，用户或 Agent 1 手动传递交接材料。
- 仓库不依赖固定语言或技术栈；具体检查命令由使用该模板的项目定义。

## 新项目需要补齐

- 在 `docs/ARCHITECTURE.md` 中记录真实应用组件和数据边界。
- 在产品规格中定义第一个用户路径与验收条件。
- 为项目添加能直接运行的检查与测试命令，并让 Agent 1 在每次返修后执行受影响的检查。
- 按实际宿主配置两个模型/Agent，并检查 Agent 2 的只读权限与上下文隔离能力。
