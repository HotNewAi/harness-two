# harness-two 双 Agent 工作流改造

## 目标

将通用 Agent 协作模板改造成 harness-two：每项开发工作由 Agent 1 编写和修改代码，由独立的 Agent 2 审查并反馈；Agent 1 按反馈修复，再交给 Agent 2 复查，直至通过或将明确的未决事项交由用户决策。

## 范围

- 包含：项目品牌名称、架构与产品说明、双 Agent 协作规约、两种角色提示词、初始化脚本、PR 模板、发布记录和 history。
- 不包含：绑定特定模型供应商、API 凭据、自动调用模型的运行时或 Agent SDK。

## 背景

- 相关文档：`AGENTS.md`、`docs/ARCHITECTURE.md`、`docs/design-docs/core-beliefs.md`、`docs/REPO_COLLAB_GUIDE.md`。
- 相关代码路径：`scripts/init-project.sh`。
- 已知约束：仓库当前是文档与脚本模板，没有应用程序或模型调用实现；双模型执行需通过两个独立模型会话或宿主平台的 Agent 能力接入。

## 风险

- 风险：不同宿主平台可能不能强制模型具备只读权限或自动交接。
- 缓解方式：明确 Agent 2 的只读职责，并提供可复制提示词与人工交接步骤；不给出已自动化执行的承诺。
- 风险：审查意见可能无证据或与需求冲突。
- 缓解方式：要求每条发现引用文件/位置、影响和复现方式；由 Agent 1 验证修复，冲突项交用户裁决。

## 验证方式

- 命令：`bash -n scripts/init-project.sh` 通过；`git diff --check` 通过。
- 初始化行为：在隔离副本中以包含引号、美元符号、& 和斜杠的项目名运行脚本，README/AGENTS 标题保留了字面值，上游 URL 未变。
- 手工检查：Agent 2 完成 3 轮只读检查，覆盖流程、角色边界、文档一致性、初始化脚本与归档记录；发现项均已修复。
- 名称检查：README、入口文档和初始化脚本以 harness-two 作为模板基名；上游 GitHub 仓库链接保留为来源引用。
