# 双 Agent 开发与审查流程

harness-two 将一次开发任务拆成两个彼此独立的职责：Agent 1 实现，Agent 2 审查。两者可以使用不同模型，也可以由同一宿主平台的两个独立 Agent 会话承载。建议选择不同模型，减少共同盲点。

当前仓库是提示词和协作约定模板，不包含模型 API、密钥管理或自动调度器。使用者需要在支持的宿主中分别启动两个模型会话，并按下面的交接步骤传递材料。

## 角色边界

### Agent 1：实现者

- 理解用户目标、仓库约束与验收条件；不清楚的关键需求先向用户澄清。
- 独立负责修改代码、配置、测试和文档，并运行适用的验证。
- 将变更 diff、需求/验收条件、验证结果和已知风险交给 Agent 2。
- 收到审查发现后逐条核实；修复有效问题，必要时说明为何某项建议不适用，并再次验证。
- Agent 1 是唯一写入工作区的 Agent。最终由 Agent 1 汇总状态和仍需用户决策的事项。

### Agent 2：审查者

- 依据用户目标、仓库规范和实际 diff 做独立审查。
- 只报告能从代码、配置、文档或验证结果支持的问题；不修改文件，不扩展任务范围。
- 优先检查逻辑错误、回归、安全、数据丢失、异常路径、兼容性、测试遗漏和文档偏差。
- 每条发现给出严重级别、文件与位置、触发条件、实际影响以及可执行的修复建议。无法确认的点标为问题或待确认，不陈述成事实。
- 没发现可操作问题时明确给出 `通过`，并指出检查范围与未覆盖项。

## 一轮任务的交接步骤

1. **明确任务**：Agent 1 确认用户目标、范围和验收标准，读取 `AGENTS.md` 指向的仓库规则。跨度大或风险高时，在 `docs/exec-plans/active/` 记录计划。
2. **实现**：Agent 1 完成一版改动，运行与改动有关的检查，保存当前 diff。
3. **交给审查**：新开或重置 Agent 2 会话，提供用户需求、验收标准、相关仓库规则、完整 diff，以及实际运行过的检查和结果。不要只给 Agent 2 Agent 1 的自我总结。
4. **审查**：Agent 2 使用 `docs/agent-prompts/agent-2-reviewer.md`。在独立上下文中只提供目标、约束、相关规范和当前 diff；不提供 Agent 1 的自我评价。两个会话有助于分离职责，但相同模型并不保证统计独立。
5. **返修**：若有可操作发现，Agent 1 逐条记录“修复 / 不采纳 / 需用户决定”及原因；修复后重新运行相关检查，并把新 diff 和处理结果交给 Agent 2 复查。工作树或需求变化后，旧审查结论失效，必须针对新 diff 重审。
6. **结束**：默认最多 3 轮审查。没有未处理的阻断或高/中影响发现且 Agent 2 明确通过时结束；低影响项需记录取舍。若意见与需求冲突、无法安全修复、验证环境不可用或达到 3 轮仍有重要分歧，Agent 1 汇总证据并请求用户决策，不得把阻塞伪报为通过。空 diff 应明确记录并结束审查。
7. **留档**：按 `docs/REPO_COLLAB_GUIDE.md` 与 `docs/HISTORY_GUIDE.md` 更新计划、history 和必要的发布记录。用户仍负责合并、发布和其他外部副作用的授权。

## 审查严重级别

- **阻断**：会导致数据丢失、权限绕过、严重安全问题或核心功能不可用，应修复或由用户明确接受风险后才能结束。
- **高**：在常见输入或路径下产生明显错误、回归或重要功能缺失。
- **中**：在明确条件下产生可复现问题，或关键边界没有验证。
- **低**：小范围健壮性、维护性或说明问题，不影响主要验收。

严重级别描述影响，不代替证据。每条发现都应能定位和复现。Agent 1 不应为了获得“通过”而隐藏未修复的高影响问题；对低级别未处理项应说明理由和后续安排。

## 推荐的交接格式

```text
任务与验收条件：
仓库约束：
本轮变更 diff：
实际运行的检查及结果：
已知风险或未覆盖范围：
上轮审查发现与处理（首轮可省略）：
```

Agent 2 应按以下结构返回：

```text
结论：需要修改 / 通过 / 被阻塞
发现：
- [严重级别] 文件:行 — 触发条件、影响、证据、修复建议
检查范围：
未覆盖或不确定项：
```

## 与具体宿主集成

把 Agent 1 和 Agent 2 的角色提示词分别配置到宿主平台的两个 Agent/模型槽位，并把 Agent 2 的工作区权限设为只读（如果宿主支持）。如果平台不支持自动转交，按上面的交接格式手动复制 diff 与结果。模型选择、温度、API 地址、令牌和具体命令由项目使用者在自己的宿主配置中维护，不写入仓库。
